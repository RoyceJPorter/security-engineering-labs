# Engineering Portfolio Standards

## Purpose

This document defines the standards, governance, and engineering practices used throughout the **Security Engineering Labs** repository.

Its purpose is to ensure consistency, professionalism, and technical integrity across all learning paths, engineering projects, and research artifacts.

---

# Mission

The Security Engineering Labs repository serves as a public engineering portfolio documenting the development of practical skills in:

- Cybersecurity Engineering
- Artificial Intelligence (AI) Engineering
- Detection Engineering
- Security Automation
- Cognitive Security Research

The portfolio emphasizes original engineering work, continuous learning, and professional software development practices.

---

# Engineering Portfolio Rules

## Rule 1 — Original Work

This repository contains original:

- Source code
- Documentation
- Engineering notes
- Diagrams
- Technical reflections
- Software projects

Projects should demonstrate understanding rather than reproduce existing material.

---

## Rule 2 — Respect Copyright

The following content will **not** be uploaded or reproduced:

- Course videos
- Instructor slides
- Proprietary PDFs
- Lab instructions
- Quiz questions or answers
- Protected diagrams
- Proprietary source code
- Copyrighted educational material

Learning is encouraged.

Redistribution is not.

---

## Rule 3 — Credit Learning Sources

Learning sources should always be acknowledged.

Example:

> Developed while completing the TCM Security Programming100: Fundamentals learning path.

Examples include:

- TCM Security
- TryHackMe
- Hack The Box
- Google
- UMGC
- Microsoft Learn
- Cisco Networking Academy

---

## Rule 4 — Build, Don't Copy

After completing a learning path:

- Build original projects
- Apply the concepts
- Document the engineering process
- Demonstrate practical understanding

The portfolio should showcase engineering ability, not duplicated coursework.

---

## Rule 5 — Interview Standard

Every project should satisfy the following question:

> Could I confidently explain every line of code during a technical interview?

If the answer is **No**, additional study or refactoring should be completed before publication.

---

## Rule 6 — Learning Path Lifecycle

### In Progress

An active learning path contains:

- README.md
- Learning objectives
- Status
- Planned topics

No exercises or projects are added until the learning path is complete.

---

### Completed

Completed learning paths include:

- Certificates
- Exercises
- Projects
- Documentation
- Engineering reflections

---

## Rule 7 — Repository Standards

Every completed learning path follows a consistent structure.

```text
Learning_Path/
│
├── Certificates/
├── Exercises/
├── README.md
```

Folders may be adapted to use **Projects/** or **Labs/** where appropriate.

---

## Rule 8 — Documentation Standards

Every learning path should include:

- Overview
- Objectives
- Technologies
- Repository Structure
- Engineering Reflection
- Real-World Applications
- Next Learning Path

---

## Rule 9 — Commit Standards

Commit messages should be short, descriptive, and action oriented.

Examples:

- Complete Programming100 learning path
- Implement Exercise 11 modules
- Add AI100 learning path
- Update repository documentation

---

## Rule 10 — Engineering Philosophy

Projects should prioritize:

1. Understanding
2. Engineering quality
3. Documentation
4. Maintainability
5. Continuous improvement

Certificates validate learning.

Projects demonstrate capability.

---

# Portfolio Development Workflow

Every learning path follows the same lifecycle.

1. Learn
2. Complete the course
3. Earn the certificate
4. Build original projects
5. Document the work
6. Perform quality assurance
7. Publish to GitHub
8. Freeze Version 1.0
9. Move to the next learning path

---

# Long-Term Goal

The Security Engineering Labs repository is intended to demonstrate continuous professional development through practical engineering work.

It serves as a living portfolio documenting the progression from foundational programming to advanced cybersecurity, AI engineering, detection engineering, and cognitive security research.
